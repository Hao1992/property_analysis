# Property Analyzer

Barcelona property intelligence — what you're actually buying into, not just the listing.

## What it does

You enter any Barcelona address and get a report that covers what estate agents don't tell you and sellers aren't legally required to disclose:

- **AI verdict** — plain-language summary generated by Claude, personalized to your buyer profile
- **Fair value estimate** — independent valuation vs. listing price, with an adjustment waterfall
- **Hidden cost breakdown** — IBI, community fees, derrama risk, energy upgrade liability
- **Tourist apartment pressure** — how many Airbnbs are in your building and within 500m
- **School quality composite** — type, language of instruction, and Google ratings
- **Noise ecosystem** — day / night / weekend scores, floor-adjusted (higher floors get a discount)
- **Neighbourhood trajectory** — is the area rising, stable, or declining?
- **7-dimension composite score** — Convenience, Safety, Property, Market, Risk, Liveability, Hidden Costs
- **Compare mode** — AI side-by-side comparison of 2–3 properties

## Why it's different from Idealista / Fotocasa / BBVA Valora

Spanish property portals show listings. This tool answers the question every buyer actually has: *"What would my life be like if I lived here, and what will it really cost me?"*

| Feature | Spanish portals | Property Analyzer |
|---------|----------------|-------------------|
| Tourist apartment saturation | ❌ | ✅ |
| School quality (not just proximity) | ❌ | ✅ |
| Floor-adjusted noise analysis | ❌ | ✅ |
| Hidden costs (IBI + community + derrama) | ❌ | ✅ |
| AI plain-language verdict | ❌ | ✅ |
| Multi-property AI comparison | ❌ | ✅ |
| Neighbourhood trajectory | ❌ | ✅ |

## Quick start (local dev)

### Prerequisites

- Python 3.11+
- Node 20+
- Docker Desktop (for Redis)
- [Claude Code](https://claude.ai/code) installed and authenticated (`claude --version`)
- Google Places API key (free tier, ~$0.50 per full analysis)

### 1. Clone and install

```bash
git clone <repo>
cd property_analysis

# Backend
python -m venv .venv && source .venv/bin/activate
pip install fastapi "uvicorn[standard]" httpx pydantic pydantic-settings redis python-dotenv

# Frontend
cd frontend && npm install
```

### 2. Configure environment

```bash
cp backend/.env.example backend/.env
# Edit backend/.env — set GOOGLE_PLACES_API_KEY at minimum
```

### 3. Start services

Three terminals:

```bash
# Terminal 1 — Redis
docker compose up redis

# Terminal 2 — Backend (from repo root)
source .venv/bin/activate
cd backend && uvicorn main:app --reload --port 8000

# Terminal 3 — Frontend (from repo root)
cd frontend && npm run dev
```

Open [http://localhost:5173](http://localhost:5173).

> **Why not Docker for everything?** The AI narrative uses `claude -p` (subprocess calling the Claude Code CLI). The `claude` binary lives on your host machine, not inside Docker. Running the backend locally means it can call the CLI without complex volume mounting.

### AI narrative: Claude Code subscription path

The narrative verdict is generated by calling the `claude` CLI as a subprocess — identical to the pattern used in voice_blog's `ClaudeCodeBackend`. No Anthropic API key is needed; it runs against the developer's existing Claude Code subscription.

```python
proc = subprocess.run(
    ["claude", "-p", "--output-format", "json",
     "--model", "sonnet", "--fallback-model", "haiku"],
    input=combined_prompt,
    capture_output=True, text=True, timeout=120,
)
```

## Scoring system

### 7 dimensions

| Dimension | What it measures | Key signals |
|-----------|-----------------|-------------|
| **Convenience** | Day-to-day access | Transit proximity (metro > bus), amenity density (log-saturated), Google quality, park access |
| **Safety** | Crime risk | Theft, vehicle crime, vandalism, night safety (Open Data BCN) |
| **Property** | Building quality | Age + ITE status, energy certificate, price vs median |
| **Market** | Investment fundamentals | Price trend, days on market, rental yield |
| **Risk** | Hidden liabilities | Structural age, flood zone, legal clarity, neighbourhood trend |
| **Liveability** | Quality of life | School quality, night noise, day noise, neighbourhood trajectory |
| **Hidden Costs** | Ongoing cost burden | IBI, community fees, derrama risk, energy upgrade liability |

### Buyer profiles (weight adjustments)

| Profile | Boosts | De-weights |
|---------|--------|------------|
| Balanced | Equal across all | — |
| Family | Liveability ×2, Safety high | Market |
| Investor | Market ×2.3 | Convenience, Liveability |
| Retiree | Convenience, Safety high | Market |
| Expat | Balanced with hidden costs emphasis | — |

### Penalty multipliers

Applied multiplicatively after the weighted sum:

| Penalty | Trigger | Multiplier |
|---------|---------|------------|
| Critical risk | Any risk sub-score < 20 | ×0.70 |
| Overpriced | Listing > 15% above fair value | ×0.90 |
| Bad energy | Certificate F or G | ×0.95 |
| Derrama risk | Derrama risk = high | ×0.93 |
| Tourist saturation | Airbnb risk = very_high | ×0.94 |

### Scoring design principles

- **Missing data = neutral, not worst-case.** If Catastro doesn't have the energy certificate or year built, the score uses the district average, not a penalty. Absence of data in a public registry is common and does not indicate a problem.
- **Floor level adjusts noise.** Each floor above ground adds ~5 points to the noise score (up to +40). A 7th-floor flat with 10 nearby bars scores very differently from a ground-floor flat.
- **Bars are convenience, not just noise.** Bars and pubs contribute positively to the Convenience amenity density score. Only nightclubs (amenity=nightclub in OSM) are weighted heavily as night-noise sources.
- **Logarithmic POI saturation.** Having 50 supermarkets nearby is not 10× better than 5. Diminishing returns are modelled with a log-saturation curve.

## API reference

### `POST /analyze`

```json
{
  "address": "Carrer de Mallorca 401, Barcelona",
  "listing_price": 480000,
  "buyer_profile": "family"
}
```

`buyer_profile`: `balanced` | `family` | `investor` | `retiree` | `expat`

Returns `AnalyzeResponse` — see `backend/models/response.py` for the full schema.

### `POST /compare`

```json
{
  "addresses": ["Carrer de Mallorca 401, Barcelona", "Passeig de Gràcia 55, Barcelona"],
  "listing_prices": [480000, 650000],
  "buyer_profile": "family"
}
```

Returns `CompareResponse` with per-property `CompareAnalysis` objects and an AI `CompareNarrative`.

### `GET /health`

```json
{"status": "ok", "service": "property-analyzer"}
```

## Caching

All full analyses are cached in Redis for 24 hours keyed on `(address, listing_price, buyer_profile)`. The `@cached` decorator in `utils/cache.py` gracefully falls back to no-cache if Redis is unavailable.

To clear the cache during development:

```bash
docker exec property_analysis-redis-1 redis-cli FLUSHALL
```

## Known limitations

| Area | Current state | Workaround |
|------|--------------|------------|
| Catastro data | Coordinate-based lookup; some addresses return no property data | Report shows "verify with seller" |
| Floor level | Comes from Catastro; often null | Default = 2nd floor noise estimate |
| Airbnb data | Quarterly CSV snapshot (Sep 2024) | Auto-downloaded on first run, cached locally |
| School quality | No Ofsted equivalent in Spain | Composite: OSM type + distance + Google rating |
| Safety data | District-level, not street-level | Barcelona has 10 districts; granularity is limited |
| Market data | Static averages (BCN 2024) | Annual growth 4.2%, yield 4.2%, DOM 55 days |
| Outside Barcelona | District safety and trajectory data is BCN-specific | Other cities fall back to national averages |
